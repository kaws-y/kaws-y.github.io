第 3 章 系统分析与设计

考点定位：综合知识选择题高频（UML 图识别、设计模式意图、内聚耦合）；案例分析「建模与设计」常客；论文素材丰富。 优先级：高。芝士架构公开课程大纲中「系统设计」为公共课重点，含界面设计、流程设计、结构化设计、面向对象设计。

1. 知识地图

子模块 核心考点 考查形式 优先级
结构化分析与设计 DFD、数据字典、模块独立性（内聚/耦合）、结构化设计 选择题 ★★★★
UML 建模 14 种图的分类与识别（用例/类/顺序/状态/活动/构件/部署等） 选择题高频 ★★★★★
面向对象设计原则 SOLID、高内聚低耦合、开闭原则 案例/选择 ★★★★
设计模式 GoF 23 种，按创建/结构/行为分类与意图辨析 选择题高频 ★★★★
界面与流程设计 界面设计原则、流程建模 选择题 ★★

2. 核心知识

2.1 结构化设计：模块独立性

  • 内聚（模块内部联系强度，越强越好）：偶然内聚 < 逻辑内聚 < 时间内聚 < 过程内聚 < 通信内聚 < 顺序内聚 < 功能内聚（最佳）。
  • 耦合（模块间依赖程度，越弱越好）：非直接耦合 < 数据耦合 < 标记耦合 < 控制耦合 < 外部耦合 < 公共耦合 < 内容耦合（最差）。
  • 设计目标：高内聚、低耦合。记忆：内聚「偶然逻辑时间过程，通信顺序功能」；耦合「非数标控外公内」。

2.2 UML 图分类（必考识别）

类别 图 主要用途
静态/结构图 类图、对象图、构件图、部署图、包图、组合结构图 描述系统的静态组成与关系
动态/行为图 用例图、活动图、状态机图 描述系统行为与流程
交互图（行为图子集） 顺序图（时序图）、通信图（协作图）、定时图、交互概览图 描述对象间消息交互

关键辨析：

  • 用例图：描述系统功能与外部参与者（Actor）的交互，用于需求捕获。关系：include（包含，必执行）、extend（扩展，条件执行）、泛化。
  • 类图：类、属性、方法与关系（关联、聚合、组合、依赖、泛化）。组合强于聚合（整体消亡则部分消亡）。
  • 顺序图：强调消息的时间顺序（纵向生命线、横向消息）。
  • 通信图：强调对象间的结构组织关系（与顺序图语义等价、可互换）。
  • 活动图：类似流程图，强调业务流程与并发（泳道）。
  • 状态机图：描述一个对象在其生命周期内的状态变化（事件驱动）。
  • 构件图：代码模块/组件的物理组织与依赖；部署图：软硬件节点拓扑与构件部署位置。

2.3 面向对象设计原则（SOLID）

原则 含义
SRP 单一职责 一个类只负责一项职责
OCP 开闭原则 对扩展开放、对修改关闭（抽象化是关键手段）
LSP 里氏替换 子类可替换父类使用而不破坏正确性
ISP 接口隔离 依赖多个专用接口优于一个庞大接口
DIP 依赖倒置 高层模块不依赖低层模块，二者都依赖抽象

另有：迪米特法则（最少知识原则）、组合优于继承。

2.4 GoF 设计模式（按意图记忆）

类型 模式 意图关键词
创建型（5） 工厂方法、抽象工厂、单例、建造者、原型 如何创建对象
结构型（7） 适配器、桥接、组合、装饰、外观、享元、代理 如何组合类/对象形成更大结构
行为型（11） 责任链、命令、解释器、迭代器、中介者、备忘录、观察者、状态、策略、模板方法、访问者 对象间职责分配与算法封装

高频辨析：

  • 工厂方法 vs 抽象工厂：前者一个产品等级结构，后者多个产品族。
  • 适配器 vs 桥接：适配器解决「已有接口不兼容」；桥接是「抽象与实现分离，各自独立变化」。
  • 装饰 vs 代理：装饰增强功能；代理控制访问。
  • 策略 vs 模板方法：策略用组合委托可变算法；模板方法用继承在父类定义算法骨架、子类覆写步骤。
  • 观察者：一对多依赖，主题状态变化时自动通知所有观察者。

2.5 界面与流程设计原则

  • 界面：一致性、可用性、反馈及时、容错（撤销/确认）、减少用户记忆负担。
  • 流程：以业务任务为中心，识别关键路径与异常分支，避免过度复杂的审批链。

3. 易混淆概念对比

对比项 关键区别
顺序图 vs 通信图 顺序图重时间顺序，通信图重对象连接结构；可相互转换
状态图 vs 活动图 状态图描述「一个对象的状态变迁」；活动图描述「一项活动的流程与并发」
聚合 vs 组合 聚合是弱拥有（部分可独立存在）；组合是强拥有（同生共死）
include vs extend include 是必选复用；extend 是条件触发的可选扩展
内聚 vs 耦合 内聚看模块内部「聚得紧不紧」；耦合看模块之间「缠得紧不紧」

4. 考试重点

  1. 给出一段图描述（如「纵向生命线展示对象间消息先后」）判断是哪种 UML 图。
  2. 给出场景选择设计模式：动态切换算法 → 策略；事件通知多对象 → 观察者；接口不兼容 → 适配器。
  3. 内聚/耦合强弱排序题（选择题常给出四个选项按强弱排列）。
  4. 类的关联、聚合、组合关系识别与多重度标注。

5. 典型例题（原创模拟题）

例题 1：系统中订单状态在「待支付 → 已支付 → 已发货 → 已完成」之间随事件变化，最适合描述这一模型的 UML 图是（　）。 A. 活动图　B. 状态机图　C. 顺序图　D. 用例图

答案：B。解析：描述单个对象生命周期内由事件驱动的状态变化是状态机图的典型用途。活动图描述流程与并发；顺序图描述对象消息时序；用例图描述功能。

例题 2：某支付系统需要对接多家第三方支付渠道，各渠道接口签名与字段不同，希望用统一接口调用。最恰当的设计模式是（　）。 A. 策略模式　B. 观察者模式　C. 适配器模式　D. 装饰器模式

答案：C。解析：把不同接口转换为统一接口属于适配器模式。策略虽也封装差异，但前提是各策略遵循同一接口；本题重点是「接口不兼容的转换」。

6. 记忆技巧

  • UML 图口诀：类对象构部包静态，用例活动状态行；顺序通信定时交互图。
  • 内聚强度（低→高）：偶逻时过通顺功。
  • 耦合强度（低→高）：非数标控外公内。
  • 创建型五模式口诀：工抽单建原（工厂方法、抽象工厂、单例、建造者、原型）。

7. 随堂测试

  1. 部署图和构件图分别描述什么？
  2. 「对扩展开放、对修改关闭」是哪个原则？
  3. 组合与聚合在对象生命周期上有何区别？
参考答案 1. 构件图描述软件构件及其依赖关系；部署图描述运行节点（软硬件）及构件在各节点上的部署。 2. 开闭原则（OCP）。 3. 组合中整体负责部分的生命周期（整体销毁则部分销毁）；聚合中部分可独立于整体存在。

9. 芝士架构资料补充

来源：《公共知识红宝书》第 3 章、《案例冲刺宝典》第 2 章。系统设计在红宝书中为超级重点★★★★★。

9.1 处理流程设计工具（★★★☆☆）

工具 特点
程序流程图 直观描述控制流，但可能随意转移、不利于结构化
N-S 图（盒图） 完全结构化，无箭头、不允许随意转移
PAD 图 面向结构化程序设计，树形二维结构，可读性好
IPO 图 输入-处理-输出，描述模块层次与数据关系
判定表 / 判定树 描述多条件复杂组合的决策逻辑

9.2 面向对象设计要点（★★★★★）

  • 类识别原则：从名词/业务对象入手，识别属性与职责；高内聚低耦合；避免万能类；领域对象与边界对象、控制对象分工（MVC 的 Model-View-Controller 对应）。
  • SOLID 落地图景：
    • SRP：一个类只有一个变化原因。
    • OCP：通过抽象与多态扩展，不改原有代码。
    • LSP：子类必须能替换父类（如正方形继承矩形可能违约）。
    • ISP：拆分臃肿接口为多个专用接口。
    • DIP：高层与低层都依赖抽象，抽象不依赖细节。
  • 另：迪米特法则（最少知识）、组合优于继承。

9.3 设计模式 23 种分类速记（★★★☆☆）

  • 创建型（5）：Abstract Factory、Builder、Factory Method、Prototype、Singleton。
  • 结构型（7）：Adapter、Bridge、Composite、Decorator、Facade、Flyweight、Proxy。
  • 行为型（11）：Chain of Responsibility、Command、Interpreter、Iterator、Mediator、Memento、Observer、State、Strategy、Template Method、Visitor。

9.4 常见图对比要点（★★★★★）

  • 用例图：系统对外提供的功能与服务（谁用系统做什么）。
  • 类图：类的静态结构及关系，不描述时间顺序。
  • 顺序图：强调消息时间顺序（生命线纵向）。
  • 通信图/协作图：强调对象间组织结构关系，与顺序图语义等价可互换。
  • 活动图：类似流程图，强调业务流程、并发与泳道。
  • 状态图：单个对象在事件驱动下的状态迁移。

案例冲刺宝典将”常见图对比”列为重点★★★★★，常以选词填空形式考查各图的识别与用途。
