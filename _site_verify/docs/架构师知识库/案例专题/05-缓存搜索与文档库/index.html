05 缓存、搜索与文档数据库

来源：《案例冲刺宝典》第 13、14、15 章。均为重点★★★★★。

一、Redis

1. 五种数据类型（★★★★★）

String（字符串/计数）、Hash（对象属性）、List（列表/队列）、Set（集合/去重）、SortedSet（有序集合/排行榜）。

2. 持久化（★★★★★）

  • RDB：定时快照，文件紧凑、恢复快，但可能丢失最后一次快照后的数据。
  • AOF：追加写命令日志，数据更安全，文件较大、恢复较慢；可配置刷盘策略。
  • 混合持久化：RDB 做全量 + AOF 做增量。

3. 集群模式（★★★★★）

模式 特点
主从复制 一主多从，读写分离；全量同步 + 增量同步
哨兵 Sentinel 监控主从，主故障自动选举新主，实现高可用（不解决容量扩展）
Cluster 数据分片（16384 槽），分布式扩容 + 高可用
  • 哨兵 vs Cluster：哨兵侧重高可用（自动故障转移），Cluster 侧重分布式分片与容量扩展，也具备高可用。

4. 生产问题（★★★★★）

  • 缓存与数据库一致性：推荐”先更新数据库，再删除缓存”（Cache Aside）；延迟双删解决并发脏读。
  • 过期删除策略：惰性删除（访问时检查）+ 定期删除（周期抽样）。
  • 内存淘汰策略：noeviction、volatile-lru、allkeys-lru、volatile-ttl 等。
  • 大 Key：拆分、压缩；热 Key：多副本、本地缓存、读写分离。
  • 缓存穿透：查不存在的数据 → 布隆过滤器 / 空值缓存。
  • 缓存击穿：热点 Key 过期 → 互斥锁 / 逻辑过期。
  • 缓存雪崩：大量 Key 同时过期 → 过期时间加随机值 / 多级缓存。
  • 分布式锁：SETNX + 过期时间 + 唯一值校验（防误删），Redlock 多节点方案。
  • 布隆过滤器：高效判断”元素一定不存在或可能存在”，用于防穿透。
  • Redis 事务：MULTI/EXEC，命令入队后顺序执行（不支持回滚）。

二、Elasticsearch（ES）

1. 核心原理（★★★★★）

  • 分词原理 Analyzer：字符过滤 → 分词 → Token 过滤（小写化、去停用词）。
  • 倒排索引：词项 → 文档列表的映射（term → docID），是全文检索高效的核心；对比正排索引（docID → 内容）。
  • 相关性算法：TF-IDF / BM25，按词频与逆文档频率计算得分排序。

2. 核心概念（★★★★★）

Index（索引库，类似数据库表）、Document（文档，类似行）、Field（字段）、Mapping（映射，定义字段类型与分词器）、DSL（查询语言）、Shard（分片，水平拆分数据与并行处理）、Replica（副本，高可用）。

3. ES vs 关系型数据库（★★★★★）

对比 关系型数据库 ES
查询 精确查询、事务、Join 全文检索、模糊匹配、高亮、聚合分析
事务 强 ACID 无事务，近实时（refresh 后可查）
适用 结构化业务数据 文本搜索、日志、海量数据检索
  • MySQL 与 ES 数据同步：双写（简单但一致性难）、定时任务批量同步、基于 binlog 的 CDC（Canal，推荐，准实时且解耦）、消息队列异步同步。

三、MongoDB

  • BSON：二进制 JSON，支持更多数据类型（日期、ObjectId、二进制），高效存储。
  • 分片集群：Shard（分片存储数据）+ Config Server（元数据）+ Mongos（路由），支持水平扩展。
  • 高可用：副本集（Replica Set），主节点写入、从节点复制，主故障自动选举（类似哨兵）。
  • 文档型 NoSQL，Schema 灵活，适合半结构化数据、快速迭代场景。
