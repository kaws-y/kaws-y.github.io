# 01 云原生架构与容器技术

> 来源：《案例冲刺宝典》第 4 章。超级重点★★★★★。

## 1. 云原生架构原则（★★★★★）
- 核心目标：让应用**充分享受云的资源优势与弹性**，快速响应业务变化。
- 主要原则：
  - **服务化原则**：单体拆分为微服务，服务自治。
  - **弹性原则**：按需伸缩（水平扩展），应对负载波动。
  - **可观测原则**：日志、指标、链路追踪三位一体。
  - **韧性原则**：容错、降级、限流、故障自愈。
  - **所有过程自动化原则**：CI/CD、基础设施即代码（IaC）。
  - **零信任原则**：默认不信任，持续验证。
  - **架构持续演进原则**：支持渐进式改造。

## 2. 云原生架构模式（★★★★★）
- 服务化架构模式、Mesh 化架构模式（Service Mesh 将通信能力下沉 Sidecar）。
- Serverless 架构模式（函数即服务 FaaS + 后端即服务 BaaS，无需管理服务器）。
- 存储计算分离模式、分布式事务模式、可观测架构模式、事件驱动架构模式。

## 3. 不好的实践（★★★☆☆）
- 单体应用直接"搬上云"（只是换了个托管环境，未享受云原生红利）。
- 应用与云平台强耦合（无法跨云迁移）。
- 忽略灰度与回滚、缺少自动化、忽略安全左移。

## 4. 容器 vs 虚拟机（★★★★★）

| 对比项 | 虚拟机 VM | 容器 Container |
| --- | --- | --- |
| 虚拟化层次 | 硬件层虚拟化（Hypervisor） | 操作系统层虚拟化 |
| 隔离性 | 强（每个 VM 有独立 Guest OS） | 进程级隔离（共享宿主机内核） |
| 启动速度 | 分钟级 | 秒级/毫秒级 |
| 资源开销 | 大（含完整 OS，GB 级） | 小（仅应用与依赖，MB 级） |
| 性能 | 有虚拟化损耗 | 接近原生 |
| 移植性 | 受限于镜像体积 | 镜像轻量、跨环境一致 |

## 5. 容器编排 Kubernetes 核心概念（★★★★★）
- **Pod**：K8s 最小调度单元，一个或多个共享网络/存储的容器。
- **Deployment**：声明 Pod 副本数与更新策略，支持滚动升级与回滚。
- **Service**：为一组 Pod 提供稳定访问入口与负载均衡。
- **ConfigMap/Secret**：配置与敏感信息管理。
- **Namespace**：资源隔离。
- **Ingress**：集群外部访问入口（HTTP/HTTPS 路由）。
- 核心能力：自愈（Pod 故障自动重启/替换）、弹性伸缩（HPA）、服务发现、滚动发布。

## 6. 典型例题套路（★★★★★）
常给出场景要求从"资源利用率、部署速度、隔离性"对比容器与虚拟机；或从弹性、可观测、韧性等原则角度分析云原生改造方案。答题时逐条对应原则并结合场景，避免只写名词。
