## 2. 核心知识

### 2.1 安全基础

- **CIA 三要素**：机密性（Confidentiality）、完整性（Integrity）、可用性（Availability）。
- **安全模型**：
  - **BLP 模型**（Bell-LaPadula）：保密性，规则「不上读、不下写」（低级别不能读高级别，高级别不能写低级别）。
  - **Biba 模型**：完整性，规则「不下读、不上写」。
- **安全原则**：最小权限、纵深防御、默认拒绝、职责分离、经济性原则。

### 2.2 密码学（必考算法归类）

| 类型 | 代表算法 | 特点 |
| --- | --- | --- |
| 对称加密 | DES、3DES、AES、RC4、**国密 SM4**（分组）、SM1/SM7 | 速度快、密钥分发难 |
| 非对称加密 | RSA、ECC、DH、**国密 SM2** | 速度慢、解决密钥分发与签名 |
| 哈希（摘要） | MD5、SHA-1/SHA-256、**国密 SM3** | 定长输出、不可逆、抗碰撞 |
| 数字签名 | RSA 签名、DSA、ECDSA、SM2 签名 | 用私钥签名、公钥验签 |

- **关键机制**：
  - 对称加密适合大数据量加密；非对称适合密钥交换与签名；混合体系（如 HTTPS）两者结合。
  - **数字签名过程**：对原文做哈希 → 用发送方私钥加密摘要 → 随原文发送；接收方用发送方公钥解密摘要并与自己计算的哈希比对，实现**认证 + 完整性 + 不可抵赖**。
  - **数字信封**：用对称密钥加密数据，再用接收方公钥加密该对称密钥。

### 2.3 PKI 与 HTTPS

- **PKI/CA 组成**：CA（认证中心，签发证书）、RA（注册机构）、证书库、密钥备份恢复、CRL（证书吊销列表）/OCSP。
- **数字证书内容**：持有者身份、公钥、CA 签名、有效期、序列号。
- **HTTPS（TLS）握手要点**：客户端发起 → 服务端返回证书（含公钥）→ 客户端验证证书链 → 生成预主密钥用服务端公钥加密发送 → 双方协商出会话密钥 → 之后用对称加密通信。
- 辨析：**证书证明「公钥属于谁」**，不是加密数据本身。

### 2.4 认证与授权

- ** Kerberos**：基于对称加密的第三方认证，票据（Ticket）机制；KDC 含 AS（认证服务）与 TGS（票据授予服务）。
- **SSO 单点登录**：一次登录访问多个系统；SAML / CAS / OAuth2 + OIDC。
- **OAuth2**：授权框架（不是认证协议），四种授权模式（授权码、隐式、密码、客户端凭证）；**OIDC** 在 OAuth2 上增加 ID Token 实现认证。
- **访问控制**：DAC（自主）、MAC（强制）、**RBAC（基于角色）**、ABAC（基于属性）。

### 2.5 攻击与防护

| 攻击 | 原理 | 防护 |
| --- | --- | --- |
| DDoS | 海量请求耗尽资源 | 限流、CDN 分发、流量清洗、黑洞 |
| SQL 注入 | 输入拼接进 SQL 改变语义 | 参数化查询/预编译、输入校验、最小权限数据库账号 |
| XSS | 注入脚本在浏览器执行 | 输出编码、CSP、HttpOnly Cookie |
| CSRF | 诱导已登录用户发请求 | CSRF Token、SameSite Cookie |
| 中间人攻击 | 窃听/篡改通信 | HTTPS、证书校验、HSTS |
| 社会工程/钓鱼 | 欺骗用户泄露凭证 | 安全意识培训、多因素认证 |

**设备**：防火墙（网络层/应用层访问控制）、IDS（入侵检测，旁路告警）、IPS（入侵防御，串联阻断）、WAF（Web 应用防火墙）、堡垒机（运维审计）。

### 2.6 安全管理

- **等级保护 2.0**：定级（一级~五级，级别越高越重要）→ 备案 → 建设整改 → 等级测评 → 监督检查；定级要素：受侵害的客体（公民/社会/国家安全）与侵害程度。
- **风险评估**：资产识别 → 威胁识别 → 脆弱性识别 → 风险计算 → 控制措施选择。
- **RTO**（恢复时间目标，最多能停多久）与 **RPO**（恢复点目标，最多丢多少数据）——注意与第 14 章可靠性呼应。
- **业务连续性计划（BCP）/ 灾难恢复计划（DRP）**：预案、演练、备份与异地容灾。

## 3. 易混淆概念对比

| 对比项 | 关键区别 |
| --- | --- |
| 对称 vs 非对称加密 | 前者速度快、密钥共享难；后者速度慢、无需共享私钥 |
| 数字签名 vs 消息认证码 MAC | 签名用私钥、具备不可抵赖性；MAC 用共享密钥，无法不可抵赖 |
| 数字签名 vs 加密 | 签名保证认证/完整性/不可抵赖，不保密；加密保证机密性 |
| BLP vs Biba | BLP 保机密（不上读不下写）；Biba 保完整（不下读不上写） |
| IDS vs IPS | IDS 旁路检测只告警；IPS 串联部署可实时阻断 |
| OAuth2 vs OIDC | OAuth2 是授权框架；OIDC 增加身份认证（ID Token） |
| RTO vs RPO | RTO 对时间，RPO 对数据丢失量 |

## 5. 典型例题（原创模拟题）

**例题 1**：关于数字签名，下列说法正确的是（　）。
A. 用接收方公钥加密摘要　B. 用发送方私钥加密摘要
C. 保证数据的机密性　D. 用于加快传输速度

**答案**：B。**解析**：数字签名由发送方用**自己的私钥**加密消息摘要，接收方用发送方公钥验签，实现身份认证、完整性和不可抵赖；它本身不保证机密性（那是加密的职责）。

**例题 2**：某系统要求「即使出现严重故障，丢失数据不超过 5 分钟」，这一指标属于（　）。
A. RTO　B. RPO　C. MTBF　D. SLA

**答案**：B。**解析**：RPO 是允许丢失的数据量（通常以时间衡量）；RTO 是允许的系统中断时长。

## 6. 记忆技巧

- CIA：**机完可**（机密、完整、可用）。
- BLP：**不上读、不下写**（保密）；Biba 反过来（完整）。
- 国密算法：**SM2 非对称、SM3 摘要、SM4 对称**。
- 攻击防护：**注入靠预编译，XSS 靠编码，DDoS 靠限流清洗**。

## 7. 随堂测试

1. 证书中的公钥属于谁？证书由谁签发？
2. 数字签名能提供哪三个安全保证？
3. RBAC 与 DAC 的主要区别是什么？

<details>
<summary>参考答案</summary>

1. 公钥属于证书持有者（主体）；证书由 CA（认证中心）签发并用 CA 私钥签名。
2. 身份认证、完整性、不可抵赖性。
3. RBAC 通过角色间接授予权限，便于集中管理；DAC 由资源所有者自主决定把权限授予谁，可传递。

## 7. 芝士架构资料补充

> 来源：《公共知识红宝书》第 13 章、《案例冲刺宝典》第 7 章（安全架构为案例超级重点★★★★★）。

### 7.1 安全架构三特性辨析（★★★☆☆，案例爱考完整性 vs 机密性）

| 特性 | 定义 | 典型例子 |
| --- | --- | --- |
| 可用性 | 确保资源在需要时可正常访问，防止故障/攻击导致服务中断 | 数据备份恢复、负载均衡、双机热备 |
| 完整性 | 保护数据不被未授权修改或破坏，确保一致性与准确性 | 文件哈希校验（MD5/SHA-1）、数字签名、数据库事务回滚 |
| 机密性 | 防止敏感信息在未授权情况下被泄露或获取 | 数据加密存储、HTTPS 加密传输、ACL |

### 7.2 公钥/私钥使用场景（★★★★★）
- **公钥加密、私钥解密** → 保证机密性（数字信封：对称密钥加密数据，公钥加密对称密钥）。
- **私钥签名、公钥验签** → 保证认证、完整性、不可抵赖性（数字签名）。
- 记忆：**加密用对方公钥，签名用自己私钥**。

### 7.3 密钥管理体系（★★★☆☆）
- 密钥全生命周期：生成 → 分发 → 存储 → 使用 → 更新 → 撤销 → 销毁。
- 密钥分发：对称密钥分发难（需安全信道或 KDC），非对称解决分发问题；Diffie-Hellman 密钥交换。
- 密钥存储：硬件安全模块（HSM）、密钥管理服务器；主密钥加密工作密钥的层次化保护。

### 7.4 访问控制技术（★★★☆☆）

| 模型 | 全称 | 特点 |
| --- | --- | --- |
| DAC | 自主访问控制 | 资源所有者自主授权，可传递，灵活性高、安全性低 |
| MAC | 强制访问控制 | 系统按安全级别强制实施（如 BLP 不上读不下写、Biba 不下读不上写），安全性高 |
| RBAC | 基于角色的访问控制 | 用户→角色→权限，便于集中管理与最小权限 |
| ABAC | 基于属性的访问控制 | 依据主体/客体/环境属性动态决策，细粒度 |

### 7.5 认证技术补充（★★★★★）
- 数字证书内容：持有者身份、公钥、CA 签名、有效期、序列号；CA 用私钥签发，验证者用 CA 公钥验签。
- Kerberos：基于对称加密的第三方认证，KDC 含 AS（认证服务）与 TGS（票据授予服务），通过 Ticket 实现单点登录。
- 多因素认证（MFA）：知识因素（密码）+ 持有因素（USBKey/令牌）+ 生物因素（指纹/人脸）。
- 黑客攻击（道德黑客）与协议工程师的认证区别：认证要验证"你是谁"，授权决定"你能做什么"。
