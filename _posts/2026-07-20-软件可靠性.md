## 2. 核心知识

### 2.1 可靠性基础

- **可靠性**：系统在**规定条件下、规定时间内**完成规定功能的能力（概率）。注意与「正确性」「可用性」的区别。
- **关键指标**：
  - **MTTF**（Mean Time To Failure）：不可修复系统的平均无故障时间。
  - **MTBF**（Mean Time Between Failures）：可修复系统平均故障间隔时间，\\(MTBF = MTTF + MTTR\\)。
  - **MTTR**（Mean Time To Repair）：平均修复时间，反映可维护性。
  - **可靠度 R(t)**：\\(R(t) = e^{-\lambda t}\\)（指数分布，λ 为失效率）；**失效率 λ = 1/MTTF**。
  - **可用度 A** = \\(MTBF / (MTBF + MTTR) = MTTF/(MTTF+MTTR)\\)。99.9% 称三个 9，99.99% 四个 9。

> **辨析**：可靠性强调「不中断运行的能力」（与时间长短相关）；可用性强调「任意时刻可提供服务的能力」（含修复速度）。MTTR 越小，可用性越高但可靠性未必改变。

### 2.2 可靠性模型（必考计算）

设各部件可靠度为 \\(R_i\\)：

- **串联系统**（任一失效则系统失效）：\\(R = \prod_{i=1}^{n} R_i\\)。系统可靠度低于任一部件。
- **并联系统**（全部失效才失效）：\\(R = 1 - \prod_{i=1}^{n}(1 - R_i)\\)。系统可靠度高于任一部件。
- **混联系统**：先化简局部串并联再逐层计算。
- **失效率近似**：串联系统 \\(\lambda \approx \sum \lambda_i\\)（指数分布下精确成立）。

> 决策意义：串联环节越多，整体可靠性越低（架构设计的「短板效应」）；提高可靠性的关键是减少关键路径串联环节或为薄弱环节加冗余（改串联为并联）。

### 2.3 容错技术

- **冗余类型**：
  - 结构冗余（硬件/软件/信息/时间冗余）。
  - **主动冗余（热备）**：多个副本同时运行，表决输出结果；恢复快、资源开销大。
  - **备用冗余（冷备/温备）**：主用故障时切换备用；资源省但切换有延迟。
- **典型技术**：
  - **N 版本程序设计**：多个独立实现的版本并行执行、多数表决（防设计故障）。
  - **恢复块（Recovery Block）**：主版本 + 后备版本，验收测试失败则切换回滚。
  - **检查点与回滚**：定期保存状态，故障后回退到最近检查点。
  - **防卫式程序设计**：前置/后置条件、异常处理。
- **高可用架构战术**（呼应第 4 章）：负载均衡、集群、故障检测与转移、限流降级熔断、异地多活。

### 2.4 可靠性测试与管理

- **可靠性测试**：在规定环境下长时间运行、采集失效数据，估计 MTTF/失效率；加速寿命测试通过提高应力缩短周期（需合理换算）。
- **软件可靠性增长模型**：如 Jelinski-Moranda、Goel-Okumoto（非齐次泊松过程 NHPP）模型，用失效历史预测剩余缺陷与可靠性增长趋势（了解层次）。
- **可靠性管理**：设定可靠性目标 → 分配指标到部件 → 设计冗余与容错 → 测试验证 → 运行监控与反馈。
- **与业务连续性**：RTO（恢复时间目标）/ RPO（恢复点目标）从业务视角约束可靠性与灾难恢复方案设计。

## 3. 易混淆概念对比

| 对比项 | 关键区别 |
| --- | --- |
| MTTF vs MTBF | MTTF 用于不可修复系统；MTBF 用于可修复系统（= MTTF + MTTR） |
| 可靠性 vs 可用性 | 可靠性看「连续无故障运行时长」；可用性看「任意时刻可服务的概率」，含修复因素 |
| 串联 vs 并联可靠度 | 串联相乘（降低）；并联 1-∏(1-R)（提高） |
| 主动冗余 vs 备用冗余 | 主动同时运行表决；备用故障后切换 |
| N 版本 vs 恢复块 | N 版本多点表决并行；恢复块主备串行 + 验收测试切换 |

## 4. 考试重点

1. 串并联系统可靠度计算（必考）：先算并联支路，再算串联整体。
2. 由失效率求 MTTF、由 MTBF/MTTR 求可用度。
3. 判断提高系统可靠性的措施（增加并联冗余 vs 减少串联环节）。
4. 容错技术归类（N 版本、恢复块、检查点回滚）。
5. RTO/RPO 与可靠性、可用性指标的对应关系。

## 5. 典型例题（原创模拟题）

**例题 1**：三个部件串联，可靠度分别为 0.9、0.95、0.99，系统可靠度约为（　）。
A. 0.95　B. 0.90　C. 0.85　D. 0.99

**答案**：C。**解析**：串联 \\(R = 0.9 \times 0.95 \times 0.99 \approx 0.846\\)，约 0.85。说明串联环节越多可靠度越低。

**例题 2**：某系统 MTBF=1000 小时，MTTR=10 小时，其可用度约为（　）。
A. 99.0%　B. 99.1%　C. 99.9%　D. 98.0%

**答案**：A。**解析**：\\(A = MTBF/(MTBF+MTTR) = 1000/1010 \approx 99.0\%\\)。

## 6. 记忆技巧

- 指标口诀：**MTTF 用到坏，MTBF 修了再来，MTTR 修多久，可用度看占比**。
- 串并联公式：**串联直接乘，并联「1 减全坏之积」**。
- 容错手段：**多跑表决（N 版本）、主备切换（恢复块）、存点回滚（检查点）**。

## 7. 随堂测试

1. 某部件失效率 λ=0.001/小时，其 MTTF 是多少？
2. 两个可靠度均为 0.9 的部件并联，系统可靠度是多少？
3. 若想提升一个由多个部件串联而成的系统可靠性，从架构上有哪些思路？

<details>
<summary>参考答案</summary>

1. \\(MTTF = 1/\lambda = 1000\\) 小时。
2. \\(R = 1-(1-0.9)^2 = 0.99\\)。
3. 减少关键路径上的串联环节；对薄弱环节增加冗余（并联或主备）；引入故障检测与快速切换、降级与容错设计，降低 MTTR 提升可用度。

## 8. 芝士架构资料补充（重点★★★★★）

> 来源：《公共知识红宝书》第 7 章。

### 8.1 可靠性六大时间指标（★★★★★）
近年爱考偏门指标，记忆后缀含义即可。

| 指标 | 英文全称 | 定义 |
| --- | --- | --- |
| MTBF | Mean Time Between Failures | 平均故障间隔时间，两次相邻故障间的平均工作时间（**含故障检测与修复时间**） |
| MTTR | Mean Time To Repair/Recover | 平均修复时间，从故障发生到恢复正常运行的平均时间 |
| MTTA | Mean Time To Acknowledge | 平均确认时间，从发出故障警报到人员确认的平均时间（A=Acknowledge 确认） |
| MTTF | Mean Time To Failure | 平均失效时间，从开始使用到出现故障的平均时间（**不含检测与修复**） |
| MTTD | Mean Time To Detect | 平均发现时间，从故障发生到被检测到的平均时间（D=Detect 检测） |

- 实际应用中 MTTR、MTTD 很小，通常认为 **MTBF ≈ MTTF**（选择题考过）。
- **失效概率 F(t)**：初始为 0，随时间增大，趋于无穷时接近 1。
- **可靠度 R(t) = 1 - F(t)**，R(0)=1，R(+∞)=0。规定时间指 CPU 执行程序指令的时间总和。

### 8.2 影响软件可靠性的 5 大因素（☆☆☆☆☆）
运行剖面（环境）、软件规模、软件内部结构、开发方法和开发环境、可靠性投入。口诀：**还（环境）闺（规模）内（内部）发（方法）钱（投入）**。

### 8.3 McCabe 环形复杂度（★★★☆☆，只考选择题）
衡量程序控制结构复杂程度，三种等价算法：
1. 流图中**线性无关的区域数**（含图外部区域）；
2. **V(G) = E - N + 2**，E 为边数，N 为结点数；
3. **V(G) = P + 1**，P 为判定结点（菱形框）数目。
- 用途：复杂度 × 适当常数可估算错误数量与开发工作量，用于比较不同设计/算法优劣。

### 8.4 可靠性设计技术（★★★☆☆，论文可展开）

| 分类 | 具体技术 | 原理 |
| --- | --- | --- |
| 容错设计 | 恢复块设计 | 程序划分为恢复块，每块含多个功能同但设计不同的程序块，检测故障切换备用块 |
| 容错设计 | N 版本程序设计 | 多个不同版本对同样输入多数表决，用不同算法/语言/测试方法确保独立 |
| 冗余设计 | 备用软件模块 | 主模块故障切换，提高可靠性但增加开销 |
| 检错技术 | 检测点机制 | 监测返回结果、运行时间，发现故障停止并报警 |
| 降低复杂度 | 简化结构 | 降低模块内部与模块间关联复杂性（复杂度是缺陷根源） |
| 系统配置 | 双机热备/服务器集群 | 心跳检测切换；某台故障其他接管 |

### 8.5 串并联可靠性公式（★★★★★）
- **串联**（全部正常才正常）：\\(R_{串联} = R_1 \times R_2 \times \cdots \times R_n\\)，任一组件失效则系统失效。
- **并联**（任一正常即正常）：\\(R_{并联} = 1 - \prod_{i=1}^{n}(1 - R_i)\\)。
- 真题出现过**串并联混合系统**，先化简局部再逐层计算。
